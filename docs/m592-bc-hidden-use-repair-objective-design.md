# M592 BC Hidden-Use Repair Objective Design

## Purpose

M592 designs the first no-oracle repair path after M591.

The problem is now specific:

```text
BC5660 has a structural hidden-to-action path, but real rollout hidden states
are action-equivalent on wrong/delayed-history diagnostics.
```

This milestone is design-only:

```text
no training
no PPO
no checkpoint promotion
no actor input change
```

## Diagnosis From M589-M591

M589 identified the objective gap:

```text
scaled L3 BC trains recurrent one-step teacher-action MSE
```

M591 identified the action-use gap:

```text
fusion hidden/context/interaction chunk shares are non-trivial,
but real wrong/delayed hidden states barely move action.
```

The evidence does not say "the network cannot use hidden." It says the current
BC objective does not make real hidden states encode action-relevant vehicle
capability.

## Rejected Repair

Do not add a direct "make actions different" loss yet.

Reason:

```text
M591 shows hidden action sensitivity is weak, but it does not prove which
action should differ or whether a difference improves outcome.
```

An ungrounded action-separation loss would optimize the diagnostic rather than
the driving problem.

Do not run PPO yet.

Reason:

```text
PPO would optimize return from a checkpoint whose hidden belief is not yet
mechanistically useful.
```

Do not add `mu`, slip, tire force, wheel-speed, or oracle feasibility to actor
inputs.

Reason:

```text
the project claim is P0 human-view no-wheel/no-oracle recurrent self-ID
```

## Selected First Repair

M592 selects a capability-supervised hidden objective:

```text
train the online-GRU hidden state to predict or rank future response envelope
targets on deployable observations and histories.
```

The existing repo already has compatible training-only targets:

```text
future_braking_deceleration
future_yaw_response
future_lateral_accel_response
```

These are generated by simulator probes from the current env state. They are
not actor inputs and must remain training/evaluation labels only.

## Objective Family

The first implementation should be a scoped objective/corpus path, not PPO:

```text
L = L_action_bc
  + lambda_regression * L_capability_regression
  + lambda_rank * L_matched_current_capability_rank
  + lambda_anchor * L_action_anchor
```

### Action BC Anchor

Keep the existing teacher-action MSE:

```text
L_action_bc = ||pi_student(o_t, h_t) - a_teacher_t||^2
```

Purpose:

```text
retain the route behavior that made BC5660 useful
```

### Capability Regression

Add an auxiliary head from `next_hidden`:

```text
capability_hat_t = g(next_hidden_t)
```

Targets:

```text
y_t = [
  future_braking_deceleration,
  future_yaw_response,
  future_lateral_accel_response
]
```

Loss:

```text
L_capability_regression = Huber(zscore(capability_hat_t) - zscore(y_t))
```

The head is training-only. The deployable actor still receives only the P0
72-value observation and recurrent hidden state.

### Matched-Current Capability Rank

For accepted M586-style pairs:

```text
visible current observation nearly matched
future capability target differs
```

Add a pairwise ranking loss on capability predictions:

```text
margin = target_delta_z * rank_scale
L_rank = softplus(margin - sign(y_left - y_right) * (hat_left - hat_right))
```

This explicitly teaches hidden state:

```text
same-looking current scene can imply different vehicle capability because the
history-response state is different
```

### Action Anchor

Do not initially force actions apart. Instead, anchor actions to BC5660/L2
teacher targets during hidden repair:

```text
L_action_anchor = ||pi_repair(o_t, h_t) - pi_bc5660(o_t, h_t)||^2
```

Purpose:

```text
first make hidden informative without destroying behavior
```

Only after capability metrics improve should a later milestone decide whether
to couple capability hidden to action or run a guarded PPO/replay step.

## Validation Ladder

### Stage A: Objective Sanity

The first M593/M594 run should prove the loss is wired:

```text
capability regression loss decreases
pair ranking loss decreases
action BC loss does not explode
P0 metadata is preserved
```

### Stage B: Hidden Prediction Gate

Run hidden-envelope or equivalent probe:

```text
response_hidden target R2 improves over base BC5660
reset_hidden does not improve by the same amount
current-response-only is reported as a reference, not a deployable shortcut
```

Suggested first thresholds:

```text
mean response_hidden R2 lift over base >= 0.03
mean response_hidden minus reset_hidden lift >= 0.03
no target has worse response_hidden R2 than base by more than 0.02
```

These are probe thresholds, not promotion thresholds.

### Stage C: Hidden-Action Probe Repeat

Only after Stage B improves should M591-style action sensitivity be repeated:

```text
wrong/delayed real hidden action distances should increase
zero-current must remain a positive control
route behavior must not collapse
```

### Stage D: Route Retention

Before any public or PPO step:

```text
route-screen v2 seed block
fresh route block
moderate-OOD route block
```

The repaired checkpoint must remain L0-safe and L2-competitive, or it is only a
mechanistic probe and not a driver candidate.

## Pass/Fail Interpretation

| result | interpretation | next |
| --- | --- | --- |
| capability loss and hidden R2 improve, action still insensitive | hidden learned capability but actor head does not use it | design action-coupling or gated PPO |
| capability loss improves only through reset/current features | objective found a shortcut | revise objective to isolate recurrent history |
| capability loss does not improve | corpus/target wiring or model capacity issue | debug implementation before training |
| hidden action sensitivity improves but route collapses | objective overfit or behavior regression | add stronger action/route anchors |
| route improves without hidden metrics | not self-ID evidence | block promotion and audit shortcut |

## Decision

```text
bc_hidden_use_repair_objective_design_admit_capability_objective_implementation
```

M592 passes because it selects a capability-grounded hidden repair objective,
keeps training labels out of actor inputs, rejects ungrounded action separation,
and pre-registers validation before implementation.
