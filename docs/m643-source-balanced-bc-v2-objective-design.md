# M643 Source-Balanced BC-v2 Objective Design

## Purpose

M643 designs the next objective layer after M641/M642 produced a usable
source-balanced sequence target corpus. This milestone does not train or update
the actor. It defines the exact objective, trainable scope, and gate order that
must exist before any BC-v2 actor change.

## Key Constraint

The M641 corpus contains:

```text
initial observation
normal recurrent hidden
variant recurrent hidden
target action sequence
normal base action sequence
variant base action
mask, source id, row id, weights
```

It does not contain the post-target observation sequence generated by executing
the target actions. Therefore M641 is not yet a full closed-loop sequence
imitation dataset. It is a bounded initial-state sequence target corpus.

Consequence:

```text
do not directly train the deployed single-step actor against every step of the
target sequence as if later observations were known
```

The safe design is to first implement an exact evaluator/loss and then, only if
that passes, a shadow sequence head or tightly gated adapter smoke.

## Actor Contract

The deployable actor input remains:

```text
P0 human-view no-wheel 72-dim frame + online GRU hidden state
```

Allowed actor information:

- current P0 observation;
- recurrent hidden state produced from command-response history;
- actuator state and previous physical commands already present in P0;
- road/free-space/obstacle geometry already present in P0.

Forbidden actor information:

- source ids;
- split labels;
- target names;
- grid names;
- candidate ids;
- margin/risk improvements;
- hidden physical parameters;
- oracle feasibility labels;
- path/reference/TTC-derived answers.

All M641 metadata remains objective metadata only.

## Objective Design

M644 should implement exact objective functions with no optimizer:

```text
u_base_seq = normal_base_action_sequence
u_star_seq = target_action_sequence
mask       = sequence_mask
w          = source-balanced row weight
```

Primary masked sequence residual:

```text
L_seq = sum_i w_i * mean_t(mask_it * ||u_pred_it - u_star_it||^2)
```

For the current deployed single-step actor, only the first action can be
directly evaluated:

```text
L_first_normal = sum_i w_i * ||pi(o_i, h_normal_i) - u_star_i0||^2
L_first_variant = sum_i w_i * ||pi(o_i, h_variant_i) - u_star_i0||^2
```

For a shadow or auxiliary sequence head:

```text
g_phi(o_i, h_i) -> [u_0, delta_u_1, ..., delta_u_K]
```

Prefer predicting deltas from the base sequence:

```text
delta_star_seq = u_star_seq - u_base_seq
g_phi(o_i, h_i) -> delta_pred_seq
u_pred_seq = u_base_seq + delta_pred_seq
```

Reasons:

- the target sequence is a small local correction around the existing BC5660
  behavior;
- delta prediction keeps the objective centered on the trusted base actor;
- exact M642 scale is already bounded by the original trust limits.

The first implementation should report both action-space and delta-space
losses, but it should not yet choose an optimizer.

## Source-Balanced Weighting

Use M641 `weight` as the objective weight. Do not reweight by raw row count.

Every exact report must include:

```text
aggregate weighted loss
per-source weighted loss
per-split weighted loss
per-target weighted loss
normal-hidden first-action loss
variant-hidden first-action loss
normal-vs-variant action gap
```

The source-heldout split is a workflow holdout for this branch. It may be used
to decide whether the objective geometry generalizes across heldout source
families, but if it is used to repair a later actor update, it cannot be called
unbiased promotion evidence.

## Trainable Scope Ladder

M643 explicitly rejects a direct full-actor update as the next step.

The allowed ladder is:

```text
M644 exact BC-v2 objective/evaluator implementation
  no training, no checkpoint

M645 head-only or shadow sequence-head smoke
  freeze actor and recurrent encoder
  train only auxiliary sequence head
  prove objective learnability and split behavior

M646 adapter or last-layer actor-coupling design
  only if M645 passes
  pre-register exact source-balanced gates and behavior retention

M647 tiny actor update probe
  only after M646 design
  no promotion unless replay, behavior, and exact objective gates pass
```

This keeps the harness from turning a diagnostic sequence corpus into an
uncontrolled actor modification.

## M644 Pass Criteria

M644 passes as an exact objective implementation if:

```text
corpus rows == 431
source_count == 9
source_weight_balanced == true
all metrics finite
normal/variant first-action metrics are reported separately
train and source-heldout summaries are reported separately
actor_parameters_changed == false
training_started == false
ppo_used == false
promoted == false
```

M644 does not need to improve any loss because it is not an optimizer.

## Later Training Gates

Any later checkpoint-producing BC-v2 update must pass gates in this order:

1. Exact source-balanced objective does not regress on train.
2. Exact source-heldout objective does not regress beyond tolerance.
3. Normal-hidden target loss improves more than variant-hidden target loss.
4. Existing BC5660 route/OOD behavior retention does not regress.
5. Current-response ablation evidence from M582/M583 is not weakened.
6. Wrong/delayed-history action screens are rerun before any outcome rollout.
7. No checkpoint promotion from objective-only improvement.

Promotion remains blocked until closed-loop replay and behavior gates pass.

## Failure Classifications

Use:

| Failure | Classification |
| --- | --- |
| exact objective cannot load corpus | `lineage_invalid` |
| source weights are not balanced | `metric_artifact` |
| train improves but source-heldout worsens | `objective_overfit` |
| actor update weakens route/OOD behavior | `behavior_regression` |
| actor update weakens prior proof rows | `proof_washout` |
| source metadata enters actor input | `contract_violation` |
