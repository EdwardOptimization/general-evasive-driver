# M45 Paired-Hidden Snapshot Export

Last updated: 2026-05-21

## Motivation

M44 showed that contrasting against zero hidden state increases reset and
zero-response action distance, but it does not transfer to hidden-swap. The next
training signal needs matched nominal/perturbed hidden states directly.

Before adding another training objective, M45 builds a reusable export harness
for matched visible observations with different recurrent hidden states.

## Implementation

New CLI:

```text
python -m autodrift.paired_hidden_snapshots
```

It reuses the hidden-swap gate's snapshot collection logic and writes:

- `pairs.csv`: one row per seed with match status and visible/hidden distances;
- `snapshots.npz`: accepted matched pairs by default;
- `summary.json`: all-pair and exported-pair counts and distance summaries;
- `manifest.json`: command metadata and artifact paths.

The NPZ contains:

```text
seed
accepted_match
nominal_step
perturbed_step
observation_distance
response_observation_distance
context_observation_distance
hidden_state_distance
nominal_observation
perturbed_observation
nominal_hidden
perturbed_hidden
```

This is deployable-observation compatible: it stores observations and recurrent
hidden states produced by the policy, not hidden vehicle parameters, rule
labels, or oracle controller modes.

## Smoke

Command:

```bash
conda run -n autodrift python -m autodrift.paired_hidden_snapshots \
  --env-config configs/ppo_m24_human_view_gru_driver.json \
  --checkpoint runs/ppo_m37_multistep_response_aux_seed1637/checkpoints/checkpoint_step_102400.pt \
  --episodes 5 \
  --seed 4200 \
  --device cpu \
  --run-dir runs/m45_paired_hidden_snapshot_smoke_seed4200
```

Result:

- seeds: 5;
- paired seeds: 5;
- accepted matches: 4;
- exported pairs: 4;
- exported observation shape: `(4, 72)`;
- exported hidden shape: `(4, 128)`.

## M37_102 Export

Command:

```bash
conda run -n autodrift python -m autodrift.paired_hidden_snapshots \
  --env-config configs/ppo_m24_human_view_gru_driver.json \
  --checkpoint runs/ppo_m37_multistep_response_aux_seed1637/checkpoints/checkpoint_step_102400.pt \
  --episodes 300 \
  --seed 4300 \
  --device cpu \
  --run-dir runs/m45_m37_102_paired_hidden_snapshots_seed4300
```

Result:

- seeds: 300;
- paired seeds: 300;
- accepted matches: 280;
- exported pairs: 280;
- accepted rate: 0.933333;
- all-pair mean hidden distance: 1.476737;
- exported accepted-pair mean hidden distance: 1.269070;
- exported accepted-pair mean observation distance: 0.328693;
- exported accepted-pair mean context observation distance: 0.096270;
- exported observation shape: `(280, 72)`;
- exported hidden shape: `(280, 128)`.

## Training Caveat

Saved hidden vectors are checkpoint-specific. If the recurrent encoder changes
substantially during training, old hidden vectors are not guaranteed to remain a
valid latent-space target. This makes the export safe for diagnostics and
careful fine-tuning from the same checkpoint, but not a generic supervised
label for arbitrary future architectures.

## Conclusion

M45 completes the data harness needed for paired-hidden objectives. The next
step should be M46: design either a conservative same-checkpoint fine-tuning
objective or an on-policy paired snapshot objective that compares matched
nominal/perturbed hidden states generated by the current policy.
