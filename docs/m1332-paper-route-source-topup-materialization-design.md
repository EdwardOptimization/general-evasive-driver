## Compatibility Audit

The older M1280 materializer is not safe to reuse directly.

Reasons:

```text
1. It calls build_fault_cases() with the early default fault profile.
2. It does not apply per-fault vehicle params_override values.
3. It assumes a single source run and raw pair_id identity.
4. It reads an intervention_run_dir generated by M1277, while M1330 already
   contains preferred/rejected source rows and source-run identity.
```

M1333 should therefore add a small dedicated materializer instead of bending the
M1280 implementation.

## Materialization Algorithm

For each M1330 accepted source pair:

```text
1. Resolve source_run_id to the correct original source-generation run.
2. Resolve scenario_id inside that source run's scenario_summary.csv.
3. Resolve condition_A_fault and condition_B_fault using the source run's
   fault_profile.
4. Apply the fault scales and params_override for that condition.
5. Roll out two fixed probe prefixes for each condition:
   - left_brake_probe: steer +0.25, throttle -1.0, brake +1.0
   - right_brake_probe: steer -0.25, throttle -1.0, brake +1.0
6. Emit command-response history frames.
7. Link each condition/probe to the same-pair opposite-condition wrong history.
```

The materializer should use the source-row preferred/rejected outcome relation:

```text
condition A:
  preferred = best_candidate_A and best_A action
  rejected  = best_candidate_B and best_B action
  margins   = margin_A_best_A and margin_A_best_B

condition B:
  preferred = best_candidate_B and best_B action
  rejected  = best_candidate_A and best_A action
  margins   = margin_B_best_B and margin_B_best_A
```

The action triplets should be stored as offline objective metadata:

```text
preferred_steer
preferred_throttle
preferred_brake
rejected_steer
rejected_throttle
rejected_brake
```

They must not be added as new actor observation channels.


`cmd_steer`, `cmd_throttle`, and `cmd_brake` are probe-prefix metadata. They
may be used to populate the previous-command fields during canonical frame
projection, but they are not additional actor inputs.

These may exist as offline metadata only.
