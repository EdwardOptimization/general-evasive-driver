# AutoDrift Observation Contract

Last updated: 2026-05-21

## Rule

The actor observation must be deployable. It may contain sensed state,
localization/perception outputs, actuator state, previous commands, and explicit
high-level task commands. It must not contain hidden simulator parameters,
oracle feasibility labels, or quantities computed from hidden vehicle/road
parameters.

`info` may still contain hidden values for logging, benchmark buckets, and
model-based baselines. `ActorPolicy` must not use `info`.

## Current Actor Frame

The clean obstacle driver frame has 18 values when `action_history_mode="full"`:

- vehicle response: body-frame `vx`, body-frame `vy`, yaw rate, sideslip, steering
  actuator state, drive/brake actuator state;
- route/task state: lateral error, heading error, current path curvature,
  along-path speed, speed reference, sideslip target;
- previous command: previous drive/brake command and previous steering command;
- obstacle perception: longitudinal obstacle distance, lateral obstacle offset,
  required lateral clearance, and time to obstacle.

With `history_length=4`, the current M8/M9 clean driver observation dimension is
72.

## Removed

`aeb_stop_distance` is removed from actor observation. It is computed from
current speed, friction, gravity, and braking assumptions. Since friction and
brake capability are hidden variables that the driver is supposed to infer, this
field was an oracle-like model feature.

The policy observation also must not include:

- `mu`, mass scale, CG shift, tire stiffness, brake scale, drive scale, or
  actuator time constants;
- `obstacle_label`;
- conventional or drift lateral capacity;
- friction-step timing or whether the friction step has already happened.

`include_privileged_params=True` remains a diagnostic or teacher-only option and
must not be used for deployable driver actors.

## Watchlist

`speed_ref` is acceptable only as an external task command. If it is generated by
clipping against true simulator friction, it indirectly leaks road friction.
Driver configs therefore set `friction_limited_speed=false`.

`beta_target` is acceptable for drift-tracking curricula, but it is a weak fit
for the final general emergency driver because it can act like an external
"please drift" command. The final AES/drift-avoidance policy should prefer a
route/free-space objective and let the actor choose stable steering or drift.

Hand-written AES baselines may read `info["mu"]` or `info["obstacle_label"]`.
Those are model/oracle baselines, not deployable RL actors.

## Missing For A Better Driver

The next observation improvements should add deployable signals rather than
oracle labels:

- lookahead path curvature or local path points instead of only current
  curvature;
- lane or road-boundary free space and obstacle free-space representation;
- obstacle velocity for dynamic obstacles;
- separate throttle and brake command/state instead of one combined
  drive/brake scalar;
- wheel speeds, slip estimates, acceleration, steering rate, and brake pressure
  if the simulator exposes them;
- carried recurrent hidden state with hidden-state reset ablation at validation
  time.
